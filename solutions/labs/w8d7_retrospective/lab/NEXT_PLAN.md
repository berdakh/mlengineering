# The next eight weeks (reference EXAMPLE)

## Option A: deploy for real and operate it

Take the gated AWS route live for two weeks under a budget alarm, then run the monitoring stack on
the deployed service. Evidence: a real deployment, a cost report, one incident write-up. Cost: money
(small, capped) and attention; risk: a public endpoint if misconfigured.

## Option B: a second project in a new domain

A tabular or text problem with public data and a business framing (e.g. demand forecasting), built
with the same engineering stack in four weeks. Evidence: transfer of the whole workflow without the
course's scaffolding. Cost: time; risk: spreading thin.

## Option C: interview-loop practice

Weekly timed coding, SQL and system-design sets with a partner, recorded. Evidence: timed performance
logs. Cost: low; risk: practising without new artifacts.

## Criteria

Close the gaps the ledger shows as not demonstrated (live deployment, system design under time
pressure); produce artifacts a reviewer can open in five minutes; keep total cost under a stated cap;
fit the target roles (model-focused ML engineer, applied scientist), which weigh evaluation and
shipping over infrastructure depth.

## Plan

- Week 1: cost and credential briefing, budget alarm, deploy flowguard on the gated route -> live endpoint and runbook
- Week 2: operate it, inject one fault, tear down -> incident note and teardown evidence
- Week 3: choose and frame a second problem in a new domain -> problem statement and split definition
- Week 4: data pipeline and baselines for the second problem -> baseline table with intervals
- Week 5: model comparison and decision -> decision memo
- Week 6: package, API and container reusing the flowguard skeleton -> release candidate
- Week 7: two timed system-design reps and a mock project interview per week -> recorded reps with rubric scores
- Week 8: final write-up of both projects and an updated ledger -> portfolio v2
