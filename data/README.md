## Pump vibration windows (synthetic)

Simulated accelerometer windows from 10 pump units. Five units develop a bearing fault part-way
through their recording. It exists so the Week 1 engineering labs run offline, quickly and
deterministically.

**What cannot be concluded from it:** anything about model quality. The fault signature is a clean
90 Hz component chosen by the generator, so a linear model separates the classes almost perfectly
(test ROC AUC about 0.999 in the reference run). Those numbers show that the *code* works; they are
not evidence about real equipment, and no lesson treats them as such.

Schema - long format, one row per sample (38,400 rows = 10 units x 30 windows x 128 samples):

| Column | Type | Meaning |
|---|---|---|
| `unit_id` | str | pump unit, `P01`-`P10`; the independent group (analogue of a subject) |
| `window_id` | int | 0-29, in time order within a unit |
| `sample` | int | 0-127, sample index within the window; sampling rate 256 Hz (0.5 s windows) |
| `vibration` | float | acceleration, arbitrary units; 38 values are missing (dropped samples) |
| `temperature_c` | float | casing temperature, constant within a window |
| `label` | int | 1 if the window is in the faulty period, else 0; constant within a window |

Generator properties worth knowing: unit-specific sensor gain (log-normal) and shaft speed, so
between-unit differences are large relative to the fault effect on amplitude features; fault severity
grows after onset; temperature drifts upward with time and rises under fault.

```bash
python data/make_pump_data.py            # regenerate
python data/make_pump_data.py --check    # compare a regeneration with the committed file (SHA-256)
```

The committed CSV is the reference. Byte-identical regeneration was confirmed with NumPy 2.5.3 /
pandas 3.0.5; other versions may format floats or draw random numbers differently.
