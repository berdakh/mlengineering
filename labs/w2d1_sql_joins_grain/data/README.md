# Northfield Pumps maintenance database (SYNTHETIC)

`maintenance.db` is a SQLite database generated by `make_db.py` (seed 20261122). Every row is
simulated. It is built to contain the situations in which queries go wrong: optional relationships,
several one-to-many branches under one parent, and NULLs with different meanings.

**What cannot be concluded from it:** anything about real maintenance operations, costs or failure
rates. Totals such as "633.8 labour hours" are properties of the generator.

```bash
python labs/w2d1_sql_joins_grain/data/make_db.py            # regenerate maintenance.db
python labs/w2d1_sql_joins_grain/data/make_db.py --check    # compare logical contents with the committed file
sqlite3 labs/w2d1_sql_joins_grain/data/maintenance.db       # if the sqlite3 shell is installed
```

No `sqlite3` shell? `python -m sqlite3 labs/w2d1_sql_joins_grain/data/maintenance.db` opens an
interactive prompt on Python 3.12+, and `lab/run.py` runs a query file on any supported version.

## Tables

| Table | Rows | Grain: one row per | Primary key |
|---|---|---|---|
| `sites` | 6 | site | `site_id` |
| `machines` | 32 | machine | `machine_id` |
| `technicians` | 12 | technician | `tech_id` |
| `work_orders` | 93 | work order | `wo_id` |
| `parts` | 12 | catalogue part | `part_id` |
| `parts_used` | 121 | part line: (work order, part) | `(wo_id, part_id)` |
| `downtime_events` | 51 | downtime event | `event_id` |

## Relationships

```
sites 1 ──< machines 1 ──< work_orders 1 ──< parts_used >── 1 parts
                     1 ──< downtime_events
technicians 1 ──< work_orders        (optional: work_orders.tech_id may be NULL)
sites 1 ──< technicians              (optional: technicians.site_id may be NULL)
```

`1 ──<` reads "one to many". `work_orders` and `downtime_events` are two independent children of
`machines`; `parts_used` resolves the many-to-many relationship between work orders and parts.
Downtime events are not linked to work orders.

## Columns

| Table.column | Type | Meaning | NULL means |
|---|---|---|---|
| `sites.site_id`, `site_name`, `region` | int, text, text | site and its region (`north`, `south`, `coast`) | never NULL |
| `machines.site_id` | int | site where the machine stands | never NULL |
| `machines.model` | text | pump model | never NULL |
| `machines.installed_date` | text `YYYY-MM-DD` | installation date | never NULL |
| `machines.decommissioned_date` | text | date taken out of service | still in service |
| `machines.criticality` | text | `low`, `medium`, `high` | never assessed |
| `technicians.site_id` | int | home site | external contractor |
| `work_orders.machine_id` | int | machine worked on | never NULL |
| `work_orders.wo_type` | text | `preventive`, `corrective`, `inspection` | never NULL |
| `work_orders.opened_date` | text | date opened (2024-01-01 to 2025-12-20) | never NULL |
| `work_orders.closed_date` | text | date closed | still open |
| `work_orders.tech_id` | int | assigned technician | nobody assigned |
| `work_orders.labor_hours` | real | hours booked | not recorded (not zero) |
| `parts.unit_cost` | real | cost of one unit | never NULL |
| `parts_used.quantity` | int | units of the part used on the order | never NULL |
| `downtime_events.start_date` | text | date the downtime began | never NULL |
| `downtime_events.hours` | real | duration | never NULL |
| `downtime_events.cause` | text | `bearing`, `seal leak`, `electrical`, `cavitation`, `operator` | not determined |

Dates are ISO-8601 text, so string comparison orders them correctly
(`opened_date >= '2025-01-01'`). SQLite has no separate date type.

## Guaranteed for every seed

The checks grade queries on this file and on a second database built with another seed. Both contain:
a site without machines; a site with machines but no corrective order opened in 2025; machines
without work orders; machines with several work orders and several downtime events; work orders with
zero, one and several part lines; technicians never assigned; a part never used and a part used only
on preventive orders; NULLs in every nullable column.
